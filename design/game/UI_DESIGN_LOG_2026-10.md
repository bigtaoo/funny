## 72. 手机字号整体放大：在可读性下限之上再乘一个系数（2026-10-01）

### 72.1 问题与归因

§49.1 的可读性下限只救得了小字：390 宽手机上 `FS.body` 仍是 **7.2 CSS px**、`FS.title` 11.6。下限也没法再往上抬——它封顶在 `bodyLg`，再高就会让「小字到分区标题」塌成一个字号（§49.1「没买到什么」）。

§52 已经量出来：**这不是朝向问题，是视口问题**。手机横屏（844×390）的设计缩放比同样是 0.361，糊得和竖屏一样，只有桌面横屏（0.71×）好看。所以「把竖屏设计宽从 1080 改窄」只能治一半，手机横屏照旧。

### 72.2 三条路，用户选了最便宜的一条

| 方案 | 收益 | 代价 |
|---|---|---|
| **字号表按视口整体放大（已选）** | 两个朝向的手机一起变大、层级不塌、桌面不动 | 图标/格子不跟着变大；溢出靠巡检逐站修 |
| 竖屏设计宽 1080→720 | 竖屏文字+图标+格子全部 ×1.5 | 61 个场景竖屏重排、战斗棋盘重做；手机横屏没修 |
| 横竖屏短边都按视口自适应 | 最彻底 | 两套版面一起返工，爆炸半径最大 |

### 72.3 做法（`client/src/render/fontScale.ts`）

```
boost(scale) = clamp(向下量化到 0.05(TARGET_BODY_CSS_PX / (BASE.body × scale)), 1, MAX_BOOST)
FS.<token>   = max(下限, round(BASE.<token> × boost ^ BOOST_WEIGHT[token]))
TARGET_BODY_CSS_PX = 10    MAX_BOOST = 1.4
BOOST_WEIGHT: micro…bodyLg 1 · label 0.85 · heading 0.75 · title 0.65 · headline 0.5 · display 0.35
```

| 视口 | 缩放 | boost | body | title | display | body CSS px |
|---|---|---|---|---|---|---|
| 390×844 竖 / 844×390 横 | 0.361 | **1.4** | 18→**25** | 32→**40** | 60→67 | 7.2→**9.0** |
| 360×640 竖 | 0.333 | 1.4 | 25 | 40 | 67 | 8.3 |
| 768×1024 竖（平板） | 0.533 | 1 | 18 | 32 | 60 | 不变 |
| 1366×768 横（桌面） | 0.711 | 1 | 18 | 32 | 60 | 不变 |

几个刻意的设计点：

- **乘在 `FS` 的 getter 上，不乘在文字工厂里**——跟 §49.1 同一个理由：`y += FS.small + 6` 这种排版算术读到的是同一个数，约 590 个调用点一个不动。
- **大字少放、小字全放**（`BOOST_WEIGHT`）。标题在手机上本来就看得清，又都住在固定高度的顶栏/标题带里，满额放大最先撑破的就是它们。指数权重保证**每一档仍严格大于下一档**（从 `small` 起；`micro`/`tiny` 跟以前一样共用下限）——这正是抬下限做不到的。
- **boost 量化到 0.05**：拖窗口几个像素不会造出一套新字号（以及新一批字形缓存）。
- **`snapFont` 不放大**。它服务的是「按控件自身尺寸算出来的字号」——控件没变大，字也不能变大。
- **只看缩放比、不看朝向**，与下限同一个输入、同一处推下去（`ScalingManager.applyScaling` → `setFontScale`）。

### 72.4 配套：按字号量出来的宽度也要跟着放大（`typeWidth`）

字变大、格子不变，最先出事的是那些**按「刚好装下 N 个等宽字符」调出来的网格**。新增 `fontScale.ts#typeWidth(px) = px × boost`，给这类宽度目标用：列数随之减少（更少、更宽的格子），而不是让文字溢出。boost 为 1 的视口上它是恒等，桌面和平板的网格一个像素不动。

用到的三处：

- **拍卖行** `aucGrid`：`AUC_CELL_W_TARGET` 340 → 手机上 476，竖屏 3 列 → **2 列**（信息列 167 → ~340 设计 px）。
- **装备背包** `equipGridColumns`：`EQUIP_CELL_W_MIN`/`TARGET` 一起放大，竖屏 3 列 → **2 列**（词条「Crit Chance +30%」不再折行压进按钮行）。
- **打造网格**（`craft.ts`）：同一个目标宽度，跟背包保持同一套列宽。

代价要认：**手机上这两页一屏能看到的格子变少了**。这是在窄屏上换大字的老实账。

### 72.5 验证

- 单测：`test/render/fontLegibilityFloor.test.ts` 新增 boost 一组（桌面/平板恒为 1、横竖同值、层级严格递增、大字少放、量化、退化输入、`snapFont` 不放大）；`equipmentGridColumns.test.ts` 加手机两列；`auctionCellInfoWidth.test.ts` 加「boost 下三条单行契约在所有手机 contentW 上仍成立」。客户端全量 vitest 绿。
- 巡检（`npm run test:portrait`，系统 Chrome）：第一次跑 390×844 报 **64 条**，只集中在拍卖行三个 tab + 装备背包——其它 40+ 站的竖屏排版都有余量吃下 1.4×。修完 72.4 后 390×844 **0 条**。全量 11 视口结果见 72.6。

### 72.6 全量巡检结果

11 个视口全量跑一遍（28.7 分钟）：英文、中文和平板、桌面的 8 个视口 **0 条**；德语三个放大视口（390×844-de、360×640-de、844×390-de）共 **47 条**，只有两个根因：

- **世界地图「Kampf-Wiederholungen」徽章**（`WorldMapPanels/hud.ts`）：`FS.label` 放大后，这个德语长词超出徽章右边、出了屏幕。凡是有世界地图 HUD 的站（worldMap、city 三站、defenseEditor 两站、friends+world）都报了一遍。修法：标签按徽章内宽 `fitFont`。
- **对局手牌卡名**（`HandView/cellDraw.ts`）：「Sturmangriff」「Bogenschütze」是单个词，`wordWrap` 断不开，在 `FS.bodyLg` 下比卡面宽。修法：每次 configure 先回到满字号量一遍，再 `fitFont` 到 `cardW - 8`。池化的卡槽不会沿用上一张卡算出的字号。

修完重跑德语三视口：**0 条**。截图核对过大厅、对局（竖屏和横屏）、世界地图（德语）、装备背包，都没有挤压。全量 vitest 4146 条通过，`tsc -p tsconfig.test.json` 和 `build:web` 都通过。

### 72.7 没做的

- **图标和格子本身没变大**——那是竖屏设计宽（72.2 第二条）才能修的那一半。**同日已做，见 §73 / ADR-105。**
- **顶栏标题被挤到下限**（拍卖行「Auction House」、装备「Equipment」）是**原有问题**，不是本轮引入：竖屏顶栏标题要 `backSize(headerH)` = 84 设计 px，右侧金币簇把带宽切到 ~130，`fitFont` 只能停在下限（§50.12 已记）。
- 真机没跑过（同 §49.1）。

## 73. 竖屏设计宽度跟着屏宽走（ADR-105，2026-10-01）

§72.2 第二条，用户当天改选。规则和理由见 [ADR-105](../DECISIONS_ADR-086-onward.md)；这里记逐站的账。

### 73.1 核心改动

| 视口 | 设计矩形（前 → 后） | 缩放 | `FS.body` CSS px | 写死的设计 px 在屏上 |
|---|---|---|---|---|
| 390×844 竖 | 1080×2337 → **780×1688** | 0.361 → **0.5** | 9.0 → 10.0 | **×1.39** |
| 360×640 竖 | 1080×1920 → **720×1280** | 0.333 → **0.5** | 8.3 → 10.0 | **×1.5** |
| 430×932 竖 | 1080×2341 → 860×1864 | 0.398 → 0.5 | — | ×1.26 |
| 768×1024 竖（平板）、全部横屏、桌面 | 不变 | 不变 | 不变 | 不变 |

- `layout/designSize.ts`（新）：`portraitDesignWidth(availW)`，`PortraitLayout` 和巡检 `auditBox.ts` 共用同一个纯函数。
- `PortraitLayout`：棋盘格 `floor(84k)`、HUD 条、手牌区、卡牌尺寸 ×k；手牌区吸收取整误差，设计高严格等于 `max(round(1920k), 宽×长宽比)`。
- `fontScale.ts`：`setFontScale(scale, 设计短边)`；`snapFont`/新增的 `snapFontDown` 封顶 = 最近档(60×短边/1080)。

### 73.2 巡检逐轮（系统 Chrome，`npm run test:portrait`）

1. **只改宽度**，390×844：10 条。顶栏标题被挤（金币字号由 53 吸到 60 档）、主城队名「Sturmvorhut」断成两行压状态、通行证 XP 说明出屏。
2. **6 个手机视口**：另冒出 360 宽一屏 59 条「字太小」——是**我自己造的**：360×640 的设计高按四条带逐项取整成 1281，巡检预测 1280，缩放差 0.08% 恰好压在下限上。改成手牌区吸收误差后消失。其余真问题集中在德语和 360 宽。
3. **根因归并**：德语任务名巨大并竖排、结算页「FIGHT AGAIN」丢图标、顶栏金币过大——全是 `snapFont(格高×k)` 以前被 `display` 截在 ~21 CSS px、现在变成 30。→ `snapFont` 封顶随短边缩（ADR-105 第二条）。一处改动消掉了这一族。
4. 剩下逐站修（下表），**全量 11 视口**后只剩横屏德语拍卖出价页 4 条——是本轮拍卖列宽改动把横屏手机也多算了一列，收窄成「只在原规则会掉到 1 列时才生效」后消失。

| 站 | 症状 | 修法 |
|---|---|---|
| 顶栏（所有带金币的页） | 金币 53→60 档，标题被挤到 8 CSS px | 金币数额 `snapFontDown`；标题图标被挤到下限以下时直接去掉而不是缩成一个点 |
| 拍卖行 | 780/720 宽掉成 1 列，半格空白 | 原规则得 1 列时，boost 只乘文字部分；仍是 1 列就让商品图从 130 缩到最小 90（`aucImgSize`）保两列 |
| 拍卖筛选条（360） | 标签被整体缩到 0.71，破下限 | 先去图标、再 `fitFont`、最后才缩 |
| 主城建造队列 | 「Stadtmauer Lv.10 · noch 1:29:26」钻到加速按钮下面 | 按按钮左侧剩余宽度 `fitFont`，仍放不下就折行，面板随之变高 |
| 主城建造格（360） | 方正度规则选了 6 列 105 宽，名字折进等级行 | 列宽下限 0.7×目标宽，再窄就回到经典 3 列 + 滚动 |
| 主城队伍卡 | 单个长词被 `breakWords` 拆两行压状态 | 单行，`fitFont` 到文字列宽 |
| 主城队伍卡状态（360） | 「Injured 28m」折行压到「Heroes 5」 | 状态也单行 `fitFont`；德文到下限仍折行时，下一行按状态实测高度往下排 |
| 通行证 | XP 说明一行出屏；XP 状态 0.55 下限缩不进 | 说明按列宽折行（单行时行距不变）；状态先 `fitFont` 再缩 |
| 防守编辑器（360 德） | 三按钮簇 2× 在单独一行仍比屏宽，「Truppen auffüllen」出左边 | 在 2/1.5/1 里取放得下的最大倍数 |
| 活动页空状态（360 德） | 「Keine aktiven Events im Moment」比屏宽 | 按 86% 页宽折行居中 |
| 卡牌·皮肤页（360） | 未加遮罩的网格把跨底栏的卡画在底栏之上 | 皮肤网格画完后把底栏节点重新挂到最上层（命中区本来就是底栏优先） |
| 对局手牌（德） | 「Meteoreinschlag」到下限仍比 112 宽的卡宽 | 到下限还放不下就允许词内断行，底部锚定、第二行往上长 |

### 73.3 读图结论（390×844 前后对比，48 张）

- **明显变好**：卡牌名册（立绘、星、属性都大了一圈）、装备背包（图标、星、按钮）、商店、设置、好友、大厅底栏。
- **基本不变**：签到月历（格内全是 `ch` 的比例，本来就按屏高排）、对局棋盘（按 k 缩，屏上同尺寸）、世界地图（缩放梯子按宽度比例）。
- **代价**：家族成员名更早出省略号（按钮变大）；主城建造格因队伍区变高而略矮；关卡准备页剧情文字因上方两块变高，退了一档字号；结算页主按钮在 390 宽丢了剑图标（按钮宽按屏宽比例，字随封顶回到原 CSS 大小后应恢复——以最后一轮截图为准）。
- **最后一轮**（sweep5：844×390 德、360×640、390×844、360×640 德）**0 条发现**；读图复核大厅、对局、名册、拍卖、主城、通行证，只补了上表「队伍卡状态」一条，补后 city 站 360/390 × en/de/zh 重跑 6/6 过。

### 73.4 测试

- 单测：`PortraitLayout.test.ts` 新增宽度规则 + 「设计高与巡检预测逐像素一致」；`fontLegibilityFloor.test.ts` 改按横屏手机（0.361）写原有算术、另加竖屏 0.5 一条和 `snapFont` 封顶一组；`auctionCellInfoWidth.test.ts` 加「360–539 宽每个手机都 ≥2 列且三条单行契约成立」。
- `test:ui` 7 条按旧 1080 前提写的用例：前提本身仍有意义的（3 列装备、名字略宽、签到格高、皮肤格宽）改用 540 宽视口重建同一个 1080 设计框；描述手机的（防守编辑器 360 德、世界地图路由）改成新缩放。
- 全量：vitest 4202、`test:ui` 3178、`test:sim` 13 全过；`build:web` 过。`tsc -p tsconfig.test.json` 报 `friendsOrgBusyLock.ui.ts` 一处类型错误——基线上就有，不是本轮。
